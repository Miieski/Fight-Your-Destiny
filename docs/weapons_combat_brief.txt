---------------------------------------------------------------------
USE SUB-AGENTS. Brief each one with this document and the existing combat code. Rules: at most 2 sub-agents running at the same time
(usage limits), only ONE agent controls Studio at a time, strict file ownership, each returns a report with the exact APIs/names it created,

 - **Animation sub-agent** (owns `Animations/`, `GameClient/Controllers/Combat/Animations.luau`, `Config/CombatAnimations.luau`)

 - **SFX sub-agent** (owns the sound registry in `Util/Sfx.luau`, `Config/CombatSfx.luau`, sound assets)
 The main agent integrates (`CombatService`, input, hit-stop, camera) and keeps the server logic.
 The sub-agents can start with the CURRENT weapon models (attachment names are fixed) so nothing has to be redone when the new models arrive.

4A. COMBAT FEEL (applies to all weapons)
 - **Combo chain on the attack input (M1):** each press/hold continues the combo; the combo index resets after 0.8 s without attacking; the last hit
   is a finisher with a bigger effect, more knockback and a longer hit-stop.
 - **Hit-stop:** on a confirmed hit, freeze the attacker's animation speed to 0.05 for 0.04-0.08 s (0.12 s for finishers and Heavy). Client-side feel only.
 - **Camera:** small shake on hit (scaled by weapon, Settings toggle respected), short FOV pulse on finishers.
 - **Lunge:** each attack steps the player forward 2-4 studs (Dagger 1.5, Heavy 3, Spear 4) with a smooth LinearVelocity impulse; **aim assist:** the
   attack turns toward the nearest enemy within 15 studs (essential on mobile).
 - **Cancel rules:** Roll cancels any attack recovery; Block cancels the recovery of everything except finishers; attacks cannot start during a roll.
 - **Dash/roll:** 12 studs, i-frames per DESIGN.md, an afterimage trail (3 ghost copies fading in 0.25 s), dust puff, whoosh.
 - **Animation speed** scales with the weapon's hits/sec and the Dexterity attack-speed bonus (cap +15%).
 - **Enemy reactions:** short flinch animation, knockback (not for mini-bosses/bosses), damage numbers pop (crits bigger, yellow, with a small shake),
   combo hit counter near the crosshair/HUD that fades after 2 s.
 - **Server:** hit detection stays on the server (shapes from the combat section of docs/enemies_npcs_pets_brief.txt). The server fires a `Shot`/`Hit`
   event so other players see the swing, trail and impact. Animation/VFX/SFX never decide damage.
 - Performance: pooled VFX objects, no per-frame allocations, a global cap on simultaneous effects, Low FX setting halves particles and disables
   afterimages and shakes.

4B. ANIMATIONS (7 categories; R15 avatar). Per category provide:
 Idle (stance with the weapon) | Run (holding the weapon) | Equip (draw) | Attack combo | Block (hold, guard pose) | Block-hit reaction.
 Shared set: Roll (forward/back/left/right or one directional animation), Hit reaction, Death, Spawn/respawn.
 | Category | Combo | Feel |
 |---|---|---|
 | Sword | 4 hits: right slash, left slash, rising slash, finisher spinning slash (small AoE) | fluid, balanced |
 | Spear | 3 hits: thrust, thrust, long lunging thrust that pierces | long reach, forward lunges |
 | Heavy | 2 hits: overhead slam with ground shockwave, wide horizontal smash | slow, heavy, big hit-stop and shake |
 | Dagger | 5 fast hits alternating hands, finisher double-slash | very fast, tiny lunges, crit sparks |
 | Ranged | one shot per click: bow draw and release or gun fire with recoil, quick aim stance | precise, no combo, short recovery |
 | Magic | one cast per click: staff raise, cast circle, release (projectile or area) | readable casting pose |
 - Pipeline: first run a **pilot** with the Sword combo end to end (animation + trail + sound + hit-stop), validate the feel, and then do the other
   categories. Choose the most reliable animation pipeline and write the decision in docs/NIGHT_LOG.md:
   (1) real Roblox animation assets (KeyframeSequence authored in Studio, the owner publishes them with the Animation Editor, ids stored in
   `Config/CombatAnimations.luau`), which replicate natively; or (2) procedural keyframe data played by an `AnimPlayer` module on each client (Motor6D),
   driven by replicated attributes, if publishing cannot be automated tonight. Animation events/markers at the exact hit frame trigger hits, VFX and SFX.
 - Each animation: 24-60 fps keyframes, correct priority (Action), looped flags, weight/fade times, no foot sliding, readable anticipation, strong poses.
 - Naming: `<Category>_Idle`, `<Category>_Run`, `<Category>_Attack1..N`, `<Category>_Block`, `Shared_Roll`, ...

4C. VFX (inspired by the Blox Fruits feel but original)
 - Per category: **slash arcs** (Sword/Dagger: crescent meshes + Trails from `TipAttachment`), **thrust lines and a pierce streak** (Spear), **ground cracks and
   shockwave rings with debris** (Heavy), **muzzle flash, arrow/bullet trails, impact sparks** (Ranged),
   **cast circle, charged orb, projectile with trail, area burst** (Magic).
 - Shared: hit sparks (flash + a few shards), crit burst, block spark and shield flash, roll dust and afterimage, enemy hit flash, death dissolve,
   damage-number style, weapon trail color by **rarity** (Common none, Uncommon green ... Secret rainbow), subtle zone-element tint of the trail
   (Plains green, Desert gold, Jungle lime, Tundra icy blue; the rest later).
 - Store every effect under `ReplicatedStorage/Assets/VFX/<Category>_<Name>`; played through one `VFX.play(name, cframe, options)` helper, pooled,
   with Low FX variants. Mobile-friendly particle counts.

4D. SFX
 - Per category: swing whoosh (3 pitch variants per hit of the combo), finisher whoosh, impact on flesh/metal/stone (3 variants each), crit sting,
   Heavy slam boom, Dagger quick slashes, bow draw/release and gun shot, magic charge/cast/explosion.
 - Shared: roll whoosh, block clang, block break, hurt, death, level of rarity chime reuse, UI unaffected.
 - Use free, public audio from the Toolbox (sanitize and verify each plays; Roblox restricts private audio), pitch variation +-5%, never repeat the same
   variant twice in a row, route all sounds through the existing SoundGroups (PlayerFX volume), and cap simultaneous sounds. List any missing sounds
   in the final report.
